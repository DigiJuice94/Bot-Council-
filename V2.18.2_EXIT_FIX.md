# Bot War Room V2.18.2 — Position Guardian Exit Liquidity Fix

The log error:

`Paper SELL rejected: estimated live-route/liquidity impact ... exceeds 175 bps limit`

was trapping positions in `exit_pending`. Guardian retried the same full exit every five seconds, so the position could remain open precisely when liquidity was deteriorating.

## Fix

### 1. Different SELL limits by purpose
- BUY: unchanged at 135 bps
- staged TP/TRIM: up to 750 bps in paper mode
- full Guardian EXIT: distressed liquidation path, up to a modeled 90% price impact

### 2. Full exits no longer deadlock
If a Guardian full exit is necessary and the normal liquidity estimate is worse than the usual limit, PAPER mode records a distressed exit instead of throwing and leaving the position trapped.

This is intentionally paper-only behavior. It records the damage rather than pretending the bad liquidity did not exist.

### 3. Liquidity model is bounded
The old linear formula could output nonsensical values such as 23,829 bps (>238%). V2.18.2 uses a bounded constant-product-style curve that behaves similarly for small trades but cannot produce impossible negative execution prices.

### 4. SELL slippage now affects proceeds
Previously SELL `filledUsd` deducted only fees while `fillPrice` showed slippage. That understated losses. V2.18.2 reduces actual simulated SELL proceeds by the modeled slippage as well.

So if the Council enters an illiquid token and has to dump it at terrible impact, the paper wallet takes the loss. That result can then feed Runner/Dumper and future Exit Genome research.

Hard contract/security exit triggers are unchanged.
