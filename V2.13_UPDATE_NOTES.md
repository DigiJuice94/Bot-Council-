# Bot War Room V2.13 — Provider Waterfall + Paper Exploration

This update is designed for the observed problem where the autonomous scanner evaluated thousands of real candidates but created zero paper positions.

## What changes

- Keeps deterministic hard vetoes for **verified** unsafe conditions: cannot sell, honeypot, top-10 >80%, bundles >25%, active Solana mint/freeze authority, too little liquidity, portfolio kill switches.
- In **paper mode only**, missing critical-provider evidence becomes a severe warning and reduces starter size instead of automatically killing every candidate. Set `PAPER_FAIL_CLOSED_UNKNOWN=true` to restore the old behavior.
- Adds optional provider redundancy:
  - Moralis for Solana Pump.fun discovery, Solana swap/quality context, and EVM holder analytics.
  - Bitquery for additional real-time Solana wallet-flow context.
  - Public Solana RPC fallback for mint/freeze authorities and top-10 concentration when Helius/custom RPC is unavailable.
  - 0x Solana route verification after Jupiter.
- Jupiter and 0x are **not required** to create a paper fill. If both are unavailable, paper mode uses observed live DEX liquidity plus the internal slippage model. No real transaction is signed.
- Adds a small PAPER exploration lane for qualifying `WATCH` decisions so the system can gather evidence instead of learning nothing from a day of zero trades.
- Adds a decision-funnel dashboard showing candidates, risk passes, WATCH decisions, BUY signals, paper buys, exploration buys, top rejection reasons, provider coverage, and shadow reviews.
- WATCH/SKIP candidates that are not executed are revisited after a configurable review window to identify missed runners.

## New optional Railway variables

```env
MORALIS_API_KEY=
BITQUERY_API_TOKEN=
ZEROEX_API_KEY=
SOLANA_WALLET_ADDRESS=

PAPER_EXPLORATION_MODE=true
PAPER_EXPLORATION_MIN_CONVICTION=58
PAPER_EXPLORATION_MIN_ALPHA=48
PAPER_EXPLORATION_MAX_PCT=0.5
PAPER_SHADOW_REVIEW_MINUTES=15
PAPER_FAIL_CLOSED_UNKNOWN=false
```

You do not need every provider. The point of the waterfall is for the system to keep working when one source is unavailable.
