# V2.11.2 Test Report — Real Paper Feed

## Compile validation

The changed market-data, risk, launch-velocity, meme-regime, regime, learning, and type modules compiled successfully with TypeScript 5.8.3 in an isolated core compile.

## Real-data mapping fixture

A mocked **provider response** (not a fake production fallback) was used as a unit test to verify parsing behavior:

- provider token: `REAL`
- price: `$0.0042`
- live source tag: `dexscreener`
- security source tag: `goplus`
- holders: `3,200`
- top-10 concentration derived from provider holder percentages: `21%`
- deterministic risk: PASS
- maximum starter exposure reduced to `0.5%` because bundle, smart-money, and social-velocity providers were intentionally unverified

The engine then produced a valid Council decision from that real-data-shaped snapshot. The purpose of the fixture is parser/decision-path validation; it is not a profitability result.

## Fail-closed test

When the same live market candidate was returned but the security provider was unavailable, the risk gate blocked execution with:

- `Sellability verification unavailable from live security provider`
- `Honeypot verification unavailable from live security provider`
- `Solana mint/freeze authority verification unavailable`

This confirms that missing safety data is no longer silently treated as safe.

## UI validation

Source inspection confirms there is no hard-coded `$WAVE`, `$NEON`, `$FLOCK`, demo candidate, or placeholder price in the production decision card. Before the first live result, the card renders `LIVE FEED / SCANNING` with empty numeric fields.

## Production behavior expected on Railway

1. The Node server boots the autonomous loop.
2. Every scan tick rotates to the next enabled chain.
3. The direct live provider discovers a real candidate.
4. Security enrichment runs.
5. Critical unknown security fails closed; non-critical unknown data reduces size.
6. The eight-bot Council evaluates the candidate.
7. If the final decision is BUY and execution is allowed, Executor automatically creates a paper fill.
8. Position Guardian owns the open paper position and refreshes it from live market data.

No browser click is part of the execution path.
